## SDLC Goals

Every improvement-review run loads this section read-only before evaluating any finding. The canon mutates only through changes — amendments and retirements travel as docs/ideas proposals and land through the landing change's knowledge extraction; silent rewrites are prohibited.

| ID | Goal | Grounding | Status | Created | Amendments |
|----|------|-----------|--------|---------|------------|
| G-01 | Given any stage interrupted mid-tour, an agent resuming solely from the change artifacts under docs/changes/<slug>/ can continue without re-asking any settled question. | AGENTS.md section 5 (stage folders are the structural source of truth); docs/current/architecture.md; best-practice principle: structured phases with documented continuity so each request carries enough information to continue. | active | 2026-08-27 | none |
| G-02 | Every stage's happy path completes in a bounded number of CLI calls with zero zero-change round-trips, and envelope payloads carry no field that no consumer reads. | Dogfooding: the process-economy reform (docs/changes/streamline-the-sdlc-process-economy-collapse-the-authoring-s/) measured 99 percent scenario/AC text similarity and 11 late findings; decisions.md 2026-08-26 streamline rows; best-practice principle: tokens and rounds are the currency. | active | 2026-08-27 | envelope-state-flags (2026-09-02): the two misrepresenting authoring envelope flags are fixed — data.metadata.step removed at both write sites (the envelope top-level step field, recomputed every call, is the single source of truth) and semantic_complete revalued from always-true to status-derived (true exactly for ready-for-review/accepted) — so envelope payloads carry no field that misrepresents state. |
| G-03 | No engine, CLI, or validation path invokes a model or makes a discretionary decision; every engine outcome is reproducible from its inputs alone. | AGENTS.md section 2 (frozen envelope, capped catalog); docs/current/conventions.md (deterministic validation, declarative checks); best-practice principle: judgment at the call site, guardrails in the engine, never an LLM inside the engine. | active | 2026-08-27 | none |
| G-04 | Every construction error that can be rejected at write time is rejected at write time — no error class survives to review that the engine could have caught earlier. | Dogfooding: 11 review-time findings traced to one missing-note root cause; decisions.md 2026-08-26 streamline DEC-002 (write-time enforcement); best-practice principle: fail fast at the write boundary. | active | 2026-08-27 | none |
| G-05 | Every declared flag, schema field, check, workflow, and template section has a named live consumer, and unused surface is inventoried with grep evidence and removed or refuted. | Dogfooding: reform finding F4 (complexity/milestones/risks unconsumed, unused flags, inert version); src/skills/improvement-review/SKILL.md section 7 (standing unused-surface inventory); best-practice principle: the consumer test — "the review might someday" is not a consumer. | active | 2026-08-27 | none |
| G-06 | Adding a stage, agent, or deployment platform requires only new folders or renderer files — zero engine TypeScript changes — and no definition hardcodes an agent-specific path. | AGENTS.md section 2 invariants 7 and 10; test/e2e/new-stage-folder.test.ts (new stage folders need no engine change); docs/changes/add-agent-agnostic-agent-definitions-deployed-alongside-the-/ (agent layer delivered by folder scan plus renderers). | active | 2026-08-27 | none |
| G-07 | Every review round is appended by the bound reviewer agent, never deleted or rewritten, and no author reviews their own artifact. | AGENTS.md section 2 invariant 3 (append-only history); docs/current/conventions.md (review separation of duties); docs/changes/add-agent-agnostic-agent-definitions-deployed-alongside-the-/design.yaml DEC-007 (stage-reviewer bound to all four review stages, file_write deny ceiling). | active | 2026-08-27 | none |

## Workflows

| Workflow | Steps (≤5) | Entry Point | Exit Point | Evidence |
|----------|-----------|-------------|------------|----------|
| Single stage run | gate check → step machine → artifact validation → status ready-for-review | sdlc <stage-id> --change | artifact ready-for-review | src/scripts/lib/kinds/authoring.ts |
| Review gate | resolve target → validation → append round → --accept/--reject | sdlc <review-stage> --change | artifact accepted or rejected | src/scripts/lib/kinds/review.ts |
| Full pipeline | requirements → reviews → design → design-review → planning → planning-review → implementation → implementation-review → knowledge-extraction | sdlc status | knowledge-extraction complete | src/stages/*/stage.yaml (requires DAG) |
| Task implementation loop | update task status → complete tasks → finalize plan | sdlc implementation --change | implementation_status ready-for-review | src/scripts/lib/kinds/tasks.ts |
| Deploy | build bundle → copy skills + schemas + policies → render agents via platform renderer → smoke test | npm run deploy:smoke | JSON report with skills + agents arrays | bin/deploy-to-agent.ts |
| Verification | schemas → policies → templates+skills → typecheck → tests | npm run validate | exit 0 | package.json (scripts) |
| Knowledge sync | list deltas → update docs/current → mark complete | sdlc knowledge-extraction --change | docs-delta.yaml written, status complete | src/scripts/lib/kinds/aggregator.ts |
